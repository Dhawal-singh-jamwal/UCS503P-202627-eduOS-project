# EduOS Testing and Documentation Journal - Week 3-4

**Project:** EduOS - Academic Computing Platform  
**Member:** Harshit  
**Period:** Week 3-4

## Overview

During Weeks 3 and 4, I mainly worked on testing the EduOS prototype, validating the multi-user environment, and preparing the project documentation for evaluation.

The goal was to make sure that the current implementation works as a complete system rather than only as separate scripts and configuration files.

## Prototype Testing

The EduOS ISO was tested repeatedly using QEMU/KVM.

The main testing workflow was:

**Build ISO → Boot in QEMU → Check SDDM → Login as Student → Verify XFCE → Verify EduOS Application**

Testing after each major change helped identify problems in the login process, session startup, and student application behavior.

## Student Account Validation

The new student accounts were checked to confirm that they are real Linux users.

Commands such as `whoami`, `id`, `echo $HOME`, and `getent passwd` were used to verify the accounts.

The home directories were also checked to ensure that students receive separate environments.

This is important because the prototype uses native Linux authentication rather than only storing users inside the graphical application.

## Personalized Interface Testing

Different student accounts were tested to confirm that the application correctly detects the logged-in user.

Testing confirmed that:

- The correct username is detected
- The correct roll number is displayed
- Student-specific tasks are loaded
- Different accounts display different task information
- The administrative account does not receive the student interface

This verified that the current personalization mechanism works correctly.

## Automatic Startup Testing

The student application was tested after being configured as a system-wide XFCE autostart application.

The expected behavior is:

- Student account → EduOS application starts automatically
- Administrative account → Normal XFCE desktop remains available

This behavior was successfully verified during prototype testing.

## Login and Session Testing

The graphical login process was tested after the SDDM configuration changes.

When the initial session failed after successful authentication, logs were checked to identify the cause.

The issue was found to be related to the XFCE Wayland session being selected instead of X11.

After SDDM was configured to use X11, the complete login process worked correctly.

The updated SDDM manual username and password login screen was also tested after changing the theme.

## Demonstration Preparation

A structured demonstration sequence was prepared for evaluation.

The intended demonstration is:

1. Boot EduOS
2. Show the SDDM login screen
3. Log in as `student1000`
4. Show the personalized student interface
5. Verify the Linux username and home directory
6. Log out
7. Log in as another student
8. Show different assigned tasks
9. Log in as `eduos`
10. Show the normal administrative XFCE desktop

This demonstrates both the graphical features and the underlying Linux user management.
