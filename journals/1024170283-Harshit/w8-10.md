## Objectives for the Reporting Period

The objective during this period was to prepare and review functional test procedures for the newly developed EduOS features.

The work focused on ensuring that machine management, student account operations, laboratory assignments and EduLab assessments could be validated through reproducible test cases.

Another objective was to organize the results, diagrams and application screenshots required for the Software Engineering project report.

## Week 1 — Student Management and Machine Management Testing

### Work Completed

**1. Student Account Lifecycle Test Planning**

Prepared functional test scenarios for the student management system.

The scenarios covered:

- Creating student accounts.
- Verifying valid Linux usernames.
- Confirming home-directory creation.
- Editing student details.
- Disabling and enabling accounts.
- Resetting student passwords.
- Deleting existing student accounts.
- Deleting orphaned student records.

Negative cases were considered, including invalid usernames and attempts to perform operations on accounts outside the permitted student naming format.

**2. Persistent State Verification**

Prepared a test procedure to verify that student information remains available after reboot.

The procedure involves creating a new student, confirming the Linux account and home directory, logging in successfully, rebooting EduOS using the same writable state disk and verifying that the account can still authenticate.

The test also checks whether account details remain unchanged and whether duplicate records are introduced.

**3. Machine Management Test Design**

Worked on a configuration drift and recovery test case.

The procedure begins by checking that the machine is compliant with its assigned laboratory profile.

A controlled change is then introduced to simulate a missing required package.

The administrator refreshes the machine status, verifies that drift is detected, synchronizes the machine and checks whether compliance is restored.

The test includes a final functional check to confirm that the required software is operational after synchronization.

**4. Boot and GUI Verification**

Reviewed the key operations required to verify that the customized EduOS ISO boots successfully in QEMU/KVM.

These included graphical login, XFCE session startup, administrative dashboard availability and student application startup.

Also prepared checks for missing interface elements, application exceptions and incorrect navigation behavior.

## Week 2 — Evaluator, EduLab Testing and Report Preparation

### Work Completed

**1. C++ Evaluator Test Scenarios**

Prepared positive and negative test scenarios for the automated C++ evaluator.

Positive tests involved submitting correct programs and verifying that their output matched the expected results.

Negative tests included incorrect output, compilation errors, runtime errors and programs that exceeded execution time limits.

This helped distinguish between genuine evaluator defects and errors caused by the submitted program itself.

**2. Lab Submission and Grading Verification**

Prepared an end-to-end test case covering the normal lab assignment workflow.

The test involves an administrator assigning a C++ problem, a student opening the problem, executing correct and incorrect solutions, submitting the final code and the administrator viewing the stored submission.

The expected results include accurate test verdicts, saved source code, correct submission timestamps and updated assignment progress.

**3. EduLab Functional Testing**

Prepared an assessment test case covering the main EduLab workflow.

The test includes:

- Creating a timed C++ assessment.
- Adding multiple questions.
- Assigning marks to questions.
- Saving hidden test cases.
- Activating the assessment.
- Opening it from a student account.
- Checking the countdown timer.
- Navigating between questions.
- Submitting answers.
- Verifying calculated marks.

Special attention was given to ensuring that hidden test inputs and expected outputs were not displayed in the student interface.

**4. Assessment Security and Interface Checks**

Documented the expected behavior of basic assessment restrictions.

These included attempts to leave fullscreen using keyboard shortcuts, switching applications and using clipboard operations.

Also reviewed whether normal interactions with the assessment editor should trigger violation records.

The objective was to distinguish suspicious activity from normal student actions and avoid unnecessary false-positive events.

**5. Formal Software Engineering Test Cases**

Organized four major test cases using the course-provided test-case format:

1. C++ Library Removal and Recovery.
2. Student Account Creation and Persistence.
3. Lab Assignment Submission and Automatic Grading.
4. EduLab Assessment Creation and Execution.

Each test case included preconditions, numbered actions, expected system responses, a Pass/Fail field, comments and postconditions.

The test cases were prepared to provide repeatable verification procedures and supporting evaluation evidence.

**6. Final Report Documentation**

Worked on organizing the project's implementation details, test-case information and supporting screenshots for the final report.

Reviewed the placement and readability of diagrams such as the Use Case Diagram, Activity Diagram, Data Flow Diagrams, Component Diagram and Deployment Diagram.

Also organized screenshots showing:

- Administrator dashboard.
- Student management interface.
- Lab assignment management.
- EduLab assessment editor.
- Student portal.

The documentation was structured to support the project's final Software Engineering evaluation.
