# EduOS Development Journal - Week 3-4

**Project:** EduOS - Academic Computing Platform  
**Member:** Dhawal Singh Jamwal  
**Period:** Week 3-4

## Overview

During Weeks 3 and 4, I mainly worked on improving the working EduOS prototype and making the student login flow more complete.

The focus was on creating real student accounts, integrating the student application, fixing the graphical login issue, and testing the full workflow inside QEMU.

## Student Account Setup

Multiple Linux student accounts were created:

- `student1000`
- `student1001`
- `student1002`
- `student1003`
- `student1004`

Each account has its own:

- Username and password
- Linux user identity
- Home directory
- Student roll number
- Academic task data

The existing `eduos` account was kept as an administrative fallback account.

A setup script and systemd service were used to create and configure the accounts automatically during boot. This ensures that all required users exist before the graphical login screen appears.

## EduOS Student Application

A Python and Tkinter based student application was added to the system.

The application detects the currently logged-in Linux user and loads that student's academic information from `/usr/share/eduos/student-data.json`.

The application displays information such as:

- Student name
- Roll number
- Username
- Assigned tasks
- Task status
- Due information

Different students were assigned different sample tasks so that the prototype demonstrates personalized academic environments.

## Automatic Startup and Fullscreen Mode

The EduOS student application was configured to start automatically after a student logs into XFCE.

It was also modified to open in fullscreen mode so that the interface behaves more like the student's main academic workspace instead of a normal desktop application.

The `eduos` administrative account still receives the standard XFCE desktop for maintenance and debugging.

## Fixing the SDDM Login Issue

During testing, SDDM successfully authenticated users, but the XFCE session immediately closed after login.

After checking the session configuration, we found that SDDM was attempting to launch the XFCE Wayland session rather than the normal X11 session.

SDDM was then configured to force X11.

After rebuilding the ISO, the login flow worked correctly:

**Boot → SDDM Login → Student Authentication → XFCE X11 Session → EduOS Student Application**

This solved one of the major issues affecting the graphical login workflow.

## Improving the Login Screen

The default SDDM interface displayed multiple student user icons.

This would become inconvenient in a real academic environment where a machine may contain a large number of student accounts.

The SDDM theme was changed to `maldives`, allowing students to manually enter:

- Username
- Password

This creates a more practical login screen and avoids the need to scroll through user icons.

## Current State

The prototype can now:

- Boot into SDDM
- Authenticate multiple student accounts
- Start XFCE using X11
- Open the EduOS student interface automatically
- Display personalized academic information
- Maintain separate Linux identities and home directories
- Preserve a separate administrative environment
