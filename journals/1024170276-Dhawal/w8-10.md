## Objectives for the Reporting Period

The primary objective during this period was to extend EduOS from a basic academic Linux environment into a more complete platform that supports machine management, student administration, automated assessment and persistent system state.

The main development areas included:

- Implementing configuration drift detection and machine synchronization.
- Improving the student account lifecycle and deletion system.
- Integrating EduLab with the existing student portal and C++ evaluator.
- Resolving runtime errors, graphical interface issues and boot-time failures.
- Preparing a stable ArchISO build containing the newly implemented features.

## Week 1 — Machine Management and Student Account Integration

### Work Completed

**1. Machine Registration and Synchronization**

Worked on integrating the machine-management system into EduOS. Each EduOS instance is assigned a machine identity, such as `LAB-PC-001`, and associated with a laboratory profile defining the required software environment.

Integrated the EduOS Agent with the administrative dashboard to allow administrators to inspect the current machine status, identify missing packages and initiate synchronization to restore the expected configuration.

The implementation follows a desired-state management approach in which actual installed software is compared with the assigned laboratory profile.

**2. Boot-Time Registration and Setup**

Investigated a boot-time issue in which the student account restoration process could fail before machine registration completed.

The startup sequence was updated so machine registration occurs before the account restoration process. Additional recovery behavior was incorporated into the administrator's Refresh Status operation.

This improved the reliability of machine registration even when other initialization operations encountered problems.

**3. Student Account Deletion**

Worked on extending the administrative dashboard with a proper student deletion workflow.

Previously, student records with missing Linux accounts could not be deleted through the interface. The deletion logic was improved to handle both existing Linux accounts and orphaned student records.

Special attention was given to removing associated metadata, preventing accidental deletion of privileged accounts and ensuring deleted students would not be recreated automatically during subsequent boots.

**4. Persistent State Integration**

Worked on connecting user management operations to the writable EduOS state disk.

This allowed account information and other system data to remain available across virtual-machine restarts instead of being lost when the live ISO environment was rebooted.

## Week 2 — EduLab Integration and Final System Debugging

### Work Completed

**1. EduLab Assessment Integration**

Worked on integrating EduLab into the existing EduOS environment.

EduLab extends ordinary lab assignments by allowing administrators to configure timed C++ assessments, question marks and hidden test cases.

The assessment system was connected to the existing C++ evaluator so that student programs could be compiled and evaluated without duplicating the compilation and execution logic.

**2. Student Portal Improvements**

Worked on restructuring the student application to provide separate sections for normal Lab Assignments and EduLab Assessments.

This separation improved usability and ensured that the normal programming workflow remained independent of the timed assessment workflow.

Additional integration work involved loading assessments, saving student code and presenting evaluation results.

**3. Assessment Editor Debugging**

Investigated issues with the administrator's EduLab Assessment Editor, particularly inaccessible question controls and layout problems.

The interface was improved to support question selection, problem statements, marks, public examples and hidden test configuration.

The editor layout was adjusted to improve usability within the QEMU display resolution.

**4. ISO Building and QEMU Testing**

Integrated updated project files into the ArchISO profile and generated revised EduOS images.

Booted the images through QEMU/KVM and inspected system services, graphical login, student sessions and administrative functionality.

Also investigated build failures caused by using the RAM-backed `/tmp` directory as the ArchISO workspace. Subsequent builds used disk-backed directories to avoid running out of temporary storage.
