# EduOS Development Journal - 1 September 2026

**Project:** EduOS - Academic Computing Platform
**Date:** 1 September 2026

## Overview

This week we continued working on the graphical environment for EduOS, with the main goal of getting XFCE working properly inside our custom Archiso image.

## XFCE and LightDM Setup

We added the required graphical packages to `packages.x86_64`:

```text
xfce4
xfce4-goodies
xorg-server
xorg-xinit
lightdm
lightdm-gtk-greeter
mesa
network-manager-applet
```

We also removed `broadcom-wl` because the package was no longer available and was causing the Archiso build to fail.

LightDM was configured to use the XFCE session. The graphical login screen successfully appeared, proving that the basic graphical stack was working.

## Problems With Direct XFCE Startup

We initially experimented with starting XFCE directly from the Archiso TTY using:

```bash
startxfce4
```

This resulted in a black screen, so we abandoned that approach and restored the normal Archiso TTY configuration.

This showed that starting XFCE directly from `agetty` was not equivalent to using a proper display manager.

## Creating the EduOS User

We decided to use a normal `eduos` user instead of running the graphical desktop as `root`.

The intended credentials are:

```text
Username: eduos
Password: eduos
```

A script and systemd service were created to automatically create the user during boot.

Initially, the service failed because `eduos-setup` did not have executable permissions inside the generated ISO. We fixed this by adding:

```text
["/usr/local/bin/eduos-setup"]="0:0:755"
```

to `profiledef.sh`.

After rebuilding, the `eduos` user appeared correctly in LightDM and the password was accepted.

## Finding the Actual XFCE Problem

Although LightDM successfully authenticated `eduos`, the screen would refresh and return to the login screen.

The logs showed that the `eduos` session was successfully opened and then immediately closed. This meant authentication was working, but the XFCE session was exiting.

We then accessed the EduOS TTY and logged in directly as `eduos`. Running:

```bash
startx /usr/bin/xfce4-session
```

successfully launched the complete XFCE desktop.

This was the most important discovery of the day. It confirmed that:

- `eduos` user creation works
- Password authentication works
- Xorg works
- XFCE works
- `xfce4-session` works
- The remaining problem is specifically the LightDM to XFCE session startup

## Current State

The latest ISO boots successfully to the LightDM login screen.

The `eduos` account appears in the login dropdown and accepts the password `eduos`, but logging in still returns to the LightDM screen.

However, XFCE can be launched successfully by logging into a TTY as `eduos` and running:

```bash
startx /usr/bin/xfce4-session
```

Therefore, the graphical environment itself is working correctly.

## Next Step

The next task is to investigate why LightDM's XFCE session exits immediately.

One area to investigate is the XFCE session file:

```text
/usr/share/xsessions/xfce.desktop
```

which currently launches:

```text
Exec=startxfce4
```

We will test whether LightDM works better when it launches `xfce4-session` directly.

No changes have been committed yet.
